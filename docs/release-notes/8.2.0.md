### Cluster clients resolve an empty node endpoint to the node that reported it

`CLUSTER SLOTS` reports an empty endpoint for a node that does not know its own IP yet (for
example a single-node cluster without `cluster-announce-ip`) and `NULL` under
`cluster-preferred-endpoint-type unknown-endpoint`; `MOVED`/`ASK` carry an empty endpoint in the
latter case. Jedis used the empty host as-is, which resolves to the client's own loopback, so it
connected and authenticated to whatever listened on that port of the client machine. A `NULL`
endpoint failed with `NullPointerException`. Both now resolve to the host of the node that sent
the reply, with the reported port, as the Redis documentation specifies.

**Action required:** none.
