## Behavior Changes

Changes that may affect existing applications even though they are

### `MultiDbPipeline` does not re-send a batch after a failed `sync()` ([#4825](https://github.com/redis/jedis/pull/4825))

**Before:** when `MultiDbPipeline.sync()` failed while writing the batch or reading its replies, the
buffered commands were kept. `close()` calls `sync()`, so a pipeline used in try-with-resources sent
the whole batch again on a new connection, to whichever database was active by then, and each
`Response` returned the replay's result. Where nothing re-sent the batch, `Response.get()` threw
`IllegalStateException: Please close pipeline or multi block before calling this method`.

**Now**, as for `Pipeline` and `ClusterPipeline` ([#4761](https://github.com/redis/jedis/pull/4761)),
the buffered responses are completed with the failure and the commands are dropped: `sync()` rethrows
the failure, `Response.get()` rethrows it, and a later `sync()` or `close()` sends nothing. A failure
while borrowing the connection, before anything is sent, still leaves the batch buffered, so `sync()`
can be retried.

**Action required:** handle the failure from `sync()`/`close()` and decide per command whether to
re-issue it; the server may already have applied some or all of the batch.
